Super Admin Credential Security — Mandatory Policy:

The Super Admin master account credentials are deployed exclusively to the Business Owner / Managing Director. These credentials must never be shared, delegated, or stored in shared workspaces.   • Primary Administrator Onboarding: Create and delegate access to the first operational Administrator account responsible for day-to-day ERP management.
  • Credential Handover Protocol: Transfer operational access to the Administrator while retaining Super Admin credentials securely.

Module 02 · Chapter 02

User Authentication, Session Control & Password Recovery in Cinaway ERP

Target Audience All System Users — Administrators, HR Managers, Accountants, Cashiers & Field Salespersons
Responsible Person Super Admin System Administrator All Users
Objective Securely log in to the Cinaway ERP system, understand role-based dashboard redirection, manage active sessions, and recover forgotten passwords through the automated recovery workflow.
🔒
Session Security Notice:

Each user account is bound to a specific role that determines both system access scope and post-login dashboard destination. Field Salespersons are automatically redirected to the Mobile Collector terminal (/collections/rep-collector) upon login. All other roles land on the main ERP management dashboard. Never share login credentials with other users.

1 System Login & Role-Based Dashboard Redirection

Navigate to the Cinaway ERP login portal at cinawaylogistics.com and authenticate using your assigned credentials.

  • Email Address: Enter the registered email associated with your employee account.
  • Password: Enter your secure password. Passwords are case-sensitive.
  • Role-Based Redirect: Upon successful authentication, the system automatically routes you to the correct dashboard based on your assigned role — no manual navigation needed.
  • Email Verification Required: If prompted with a verification notice, open your registered inbox, locate the email from cinaway.system@gmail.com, and click "Verify My Email Address" before retrying login.

2 Secure Session Termination (Sign Out)

Always sign out properly when leaving the system — especially on shared or office devices. An active unattended session is a security risk.

  • Sign Out Location: Click your profile avatar or username in the top-right corner of the dashboard to reveal the dropdown menu, then click Sign Out.
  • Session Cleared: All active session tokens are invalidated immediately upon sign-out. You will be redirected to the login page.
  • Shared Device Protocol: On shared devices, always sign out and close the browser tab after completing your session.

3 Password Recovery — Forgot Password Workflow

If you have forgotten your password, use the automated recovery workflow to reset it securely without Administrator intervention.

  • Step A — Initiate Recovery: On the login page, click the Forgot Password? link located below the login form.
  • Step B — Enter Registered Email: Input the email address associated with your Cinaway ERP account and submit the form.
  • Step C — Check Your Inbox: Open your registered email inbox and locate the password reset email from cinaway.system@gmail.com.
  • Step D — Reset Link Validity: The reset link expires within 1 hour of dispatch. If the link has expired, repeat Step A to request a new one.
  • Step E — Set New Password: Click the link in the email, enter a new strong password, confirm it, and submit. You will be redirected to the login page upon success.
⚠
Administrator Reset Option:

If the automated recovery email is not received (check Spam/Junk), the System Administrator can manually resend the activation/reset link from User Management ➤ Employees by locating the employee record and triggering the resend action.

User Roles & Permission Matrix Configuration in Cinaway ERP

Target Audience System Administrator / Super Admin
Responsible Person Super Admin System Administrator
Objective Configure Role-Based Access Control (RBAC) by creating and managing custom or standard roles, and allocating granular permissions across operational modules to enforce the correct access hierarchy.
🛠
RBAC Governance Prerequisite:

User Roles and their permission matrices must be fully configured before registering any operational staff. Assigning an employee to a role that has incomplete or incorrect permissions may grant unintended system access or restrict critical operations. Always verify role permissions using the View action before assigning roles to staff accounts.

1 View All System Roles

Navigate to User Management ➤ User Roles from the main navigation menu.

The All User Roles dashboard displays a complete list of every role currently configured in the system. Each row includes the following action buttons:

  • View: Inspect the full permission matrix granted to this role across all ERP modules.
  • Edit: Modify the role name or adjust any of its module-level permissions.
  • Delete: Permanently remove the role. Only possible if no active employees are currently assigned to it.

To create a new role, click the Add New Role button in the top action bar.

2 Create a New Role & Define Permission Matrix

Click Add New Role to open the role creation form. Fill in all required fields:

  • Role Name *: Enter a unique, descriptive name for the role (e.g., Sales Manager, Warehouse Supervisor, Accountant).
  • Role Status: Set as Active to immediately make the role available for assignment, or Inactive to configure it without publishing.
  • Permission Matrix: The form displays a full list of all ERP modules and their sub-actions. For each module, selectively toggle the permissions this role is allowed to access:
    • View: Read-only access to that module's records.
    • Create: Ability to add new records.
    • Edit: Ability to modify existing records.
    • Delete: Ability to permanently remove records.

Click Save to commit the role and its permission matrix to the system.

3 Edit & Audit an Existing Role

  • Modify Permissions: Click Edit on any role row to update its name, status, or permission toggles. Changes take effect immediately for all users currently assigned to that role.
  • Audit Permission Coverage: Use the View action to audit the exact permissions currently active for any role before assigning it to new employees.
  • Filter Employees by Role: From the employee list, filter by role to confirm which staff members are assigned to a given permission group.
  • Verify Access: After assigning a role to an employee, ask them to log in and confirm they can access the required modules and are blocked from restricted areas.

4 Standard Role Reference & Deployment Notes

System Administrator Full access except root system and cron configurations. First role to configure post-deployment. Responsible for onboarding all other staff.
Accountant Finance, Expenses, Payroll, Chart of Accounts, Reports. No access to HR, Vehicle, or User Management modules by default.
Cashier Sales, Collections, Petty Cash, Receipts. Restricted from HR, Payroll, and administrative configuration modules.
Salesperson Mobile Collector only — route collections, receipts. Auto-redirected to /collections/rep-collector on login. No management dashboard access.

Deployment Rule:

The auto-created Super Admin account with full (*) permissions is generated immediately after database migration. This root account will not appear in the standard All User Roles list and must never be used for day-to-day operations — its sole purpose is initializing the system and onboarding the first Administrator.

Employee Onboarding, Profile Configuration & Access Delegation in Cinaway ERP

Target Audience System Administrator / HR Manager
Responsible Person System Administrator HR Manager
Objective Complete operational workflow for enrolling staff members into Cinaway ERP — capturing personal and banking details, defining organizational hierarchy (departments & designations), and delegating system access roles.
⚠
Mandatory Prerequisites Before Onboarding:

The following must be completed before registering any employee. The system enforces strict relational constraints:

  • ① User Roles configured — at least one operational role must exist (see Module 03).
  • ② Departments & Designations created — the employee form requires both to be pre-existing in the HR module before submission.

1 Set Up Departments & Designations (Mandatory Pre-Step)

Navigate to HR Module ➤ Core Setup. This presents a two-tab interface for managing the organizational hierarchy.

  • Departments Tab: Click Add Department, enter the department name (e.g., Logistics, Finance, Sales), and save. Each department can be edited or deleted from its row actions — provided no active employees are assigned to it.
  • Designations Tab: Click Add Designation, select the parent Department from the dropdown, enter the job title (e.g., Driver, Sales Representative), and save.
🚫
System Lock Rule: Departments and Designations with active employee assignments cannot be deleted. Always create these foundational units before beginning any employee registration workflow.

2 Add a New Employee & Configure Profile

Navigate to User Management ➤ Employees and click Add Employee.

  • Personal Details *: Full name, contact number, NIC / national ID, and address. All fields marked with an asterisk are mandatory.
  • Email Address *: Serves as the unique login identifier and primary key in the database. Must be a valid, accessible email inbox — the system dispatches an automated verification link immediately upon account creation.
  • Department & Designation *: Select from pre-configured dropdowns (must be created in Step 1 above). These drive HR hierarchy, payroll categorization, and reporting filters.
  • Start Date *: The employee's official joining date. This is used for EPF/ETF eligibility calculations (6-month threshold) and Gratuity milestones (60-month threshold).
  • Salesperson Switch: If the employee is a field sales representative, toggle Is Salesperson to ON. This flags them for route assignment and enables Mobile Collector access.
  • System Access Control: Toggle whether the employee is permitted to log in to the ERP system and set account status as Active or Inactive.

Click Save Employee to create the record. The system immediately dispatches an email verification link to the registered email address.

3 Email Verification & First Login Activation

After account creation, the employee must verify their email before they can log in to the system.

  • Dispatch: The system automatically sends an activation email from cinaway.system@gmail.com to the registered address.
  • Employee Action: The employee must open their inbox, locate the email, and click the “Verify My Email Address” button.
  • Link Expiry: The verification link expires after 1 hour. If expired, the System Administrator must navigate to User Management ➤ Employees, locate the employee row, and use the Resend Activation action to dispatch a fresh link.

4 Access Delegation & Role Assignment

Assign a system role to define precisely what the employee can see and do within the ERP. Navigate to the employee's profile and open the User Permissions section.

  • Select Role: Choose the appropriate role from the dropdown (configured in Module 03). The employee immediately inherits the full permission matrix of that role upon save.
  • Role Change: To modify access, select a new role from the same interface. The previous role permissions are fully replaced by the new selection.
  • Remove Access: To revoke system access entirely without deleting the employee record, toggle the Login Allowed switch to OFF, or set account status to Inactive.

5 Profile Photo, Documents & Bank Account Setup

From the employee's profile page, complete additional configuration to support payroll, compliance, and identity records.

  • Profile Photo: Click Upload Photo on the profile page to set the employee's avatar, used across the system interface.
  • Document Archive: Upload scanned identity and compliance documents (NIC, Driving License, Contracts). Drag and drop or browse to select files. Supported formats: PDF, JPG, JPEG, PNG — max 5 MB per file.
  • Bank Account Details: Add the employee's bank account from the Bank Details section within the profile page. The first bank account added automatically becomes the Default Payout Account for salary transfers and BOC PRN generation.

6 Employee Lifecycle Actions — Resignation & Deletion

⚠
Critical — Irreversible Actions:
  • Resign User: Marks the employee as Resigned. This is permanent and cannot be rolled back. The employee is immediately blocked from all future operations and system logins. All historical records are preserved for audit integrity.
  • Delete User: Completely and permanently removes the employee from the system. Use with extreme caution. This action cannot be undone and may affect linked payroll, attendance, and sales records.

7 Bulk Employee Import (Excel Upload)

For large-scale staff onboarding, navigate to User Management ➤ Employees ➤ Import Employees.

  • Download Template: Click the template download button to get the official Excel import format. Do not alter column headers.
  • Populate Data: Fill employee data into the template. Note: Email Address is the unique primary key — duplicate emails will cause row-level errors and block those entries from importing.
  • Upload & Preview: Drop the completed file into the upload area and click Upload & Preview to validate all rows before committing to the database.
  • Review & Confirm: The preview table color-codes each row as successful or error. Scroll through, resolve flagged issues in the source file if needed, and re-upload. Once satisfied, click the green Confirm Import button to finalize.

Employee Attendance Tracking & Biometric Import Management in Cinaway ERP

Target Audience HR Manager / System Administrator / Operations Manager
Responsible Person HR Manager System Administrator
Objective Review daily shift logs, perform bulk Excel imports from physical biometric fingerprint machines, and manage manual attendance corrections for accurate payroll processing.
📅
Critical Payroll Dependency:

Attendance records are a mandatory input for payroll processing. Missing or incomplete attendance logs will cause the payroll engine to automatically calculate the affected employee's salary as No-Pay for that period. Ensure all attendance data is imported and verified before initiating the monthly payroll run.

1 View Attendance Dashboard

Navigate to Attendance from the main navigation menu.

The All Attendance dashboard displays the complete roster log with the following fields per record:

  • Date: The calendar date of the attendance entry.
  • Employee Name: The registered employee linked to the record.
  • In Time: Recorded clock-in timestamp.
  • Out Time: Recorded clock-out timestamp.
  • Total Work Hours: System-calculated duration between In and Out times.
  • Source Indicator: Each record is automatically flagged as either Fingerprint (synced via Excel import from the biometric machine) or Manual (entered directly by an administrator).

The top action bar provides quick-access buttons for Import Attendance and Add Record. Row-level actions allow permanent Delete of individual entries if required.

2 Bulk Import Biometric Attendance (Excel Upload)

Click the Import Attendance button from the top action bar or the dashboard shortcut.

  • Step A — Read Format Instructions: Carefully review the data format guidelines displayed on the import page before preparing the file.
  • Step B — Export from Fingerprint Machine: Download the raw biometric attendance data file from the client's physical fingerprint machine. The export format will vary by device manufacturer.
  • Step C — Format & Map Employee IDs: Reformat the raw data to match the system's standard import template. Critically, ensure the correct Employee ID (from the ERP system) is mapped to each row. Mismatched IDs will cause row-level import errors.
  • Step D — Upload & Preview: Drag and drop the formatted file into the upload block (or click to browse), then click Upload & Preview to audit all records before committing to the database.
  • Step E — Review & Confirm: The preview table flags each row as successful or erroneous. Review error rows, correct the source file if needed, and re-upload. Once validated, click Confirm Import to finalize the batch into the database.

3 Manual Attendance Entry & Correction

Use manual entry to add or correct attendance records that were missed by the biometric import (e.g., machine failure, employee forgot to clock in/out).

Click the Add Record button from the top action bar to open the manual override form.

  • Employee *: Search and select the target employee from the dropdown.
  • Date *: Select the exact calendar date of the attendance entry.
  • In Time *: Enter the employee's clock-in time using the time picker.
  • Out Time *: Enter the employee's clock-out time.
  • Calculated Working Hours: The system dynamically computes and displays the total working duration in real-time as you enter the In and Out times. Verify this figure before saving.

Click Create Record to save the manual entry into the database. Manually created records are flagged with the Manual source indicator for audit transparency.

4 Attendance Audit & Common Import Errors

Error / Scenario Root Cause Resolution
Row flagged as error on import preview Employee ID in the file does not match any registered employee in the system. Verify the Employee ID in the ERP employee list and correct the import file, then re-upload.
No-Pay status generated in payroll No attendance record found for the employee for that month during payroll processing. Add missing records manually via Add Record before re-running payroll for that period.
Duplicate record on import Same employee and date combination already exists in the database from a previous import. Remove duplicate rows from the import file or delete the existing record from the dashboard before re-importing.
Incorrect work hours calculated In Time or Out Time entered incorrectly (e.g., AM/PM swap). Delete the incorrect record from the dashboard and re-add it manually with the corrected timestamps.

Module 06 · Chapter 06

Leave Configuration, Staff Applications & Approval Workflows in Cinaway ERP

Target Audience HR Manager / System Administrator
Responsible Person HR Manager System Administrator
Objective Configure statutory and custom leave types with annual quotas, manage staff leave application submissions on behalf of employees, and process approval or rejection decisions through the centralized HR workflow.
📋
Payroll Integration Notice:

Leave records directly impact payroll calculations. Paid leave types (where Is Paid Leave is toggled ON) are counted toward the employee's full salary entitlement for that period. Unpaid leave reduces the monthly basic salary proportionally. Ensure all leave requests are approved or rejected before the monthly payroll run is executed (see Module 07 for the complete Payroll Lifecycle).

1 Configure Leave Types & Annual Quotas

Navigate to HR Module ➤ Leave Management. The interface presents a two-tab layout: Leave Types and Leave Requests.

From the Leave Types tab, click Add New Leave Type to open the configuration popup.

  • Leave Type Name *: Enter a descriptive name (e.g., Annual Leave, Casual Leave, Medical Leave, Maternity Leave).
  • Annual Quota *: Set the maximum number of leave days permitted per year for this type (e.g., 14 days for Annual Leave).
  • Is Paid Leave: Toggle ON if this leave type counts toward the employee's full salary for the period. Leave this OFF for unpaid or no-pay leave categories.
  • Status: Set as Active to make the type available for staff applications immediately.

Click Save to create the leave type. Existing types can be edited or deleted from the row actions in the Leave Types list.

2 Submit a Leave Application on Behalf of Staff

Navigate to the Leave Requests tab and click the Add Leave Request button. The HR Manager or Administrator submits requests on behalf of employees.

  • Employee *: Search and select the target employee from the dropdown.
  • Leave Type *: Select from the pre-configured leave types (must be created in Step 1 above).
  • From Date *: Select the start date of the leave period.
  • To Date *: Select the end date. The system automatically calculates the total number of leave days from the date range.
  • Reason / Notes: Enter the reason for leave for audit records and manager reference.

Click Submit to register the leave request. Newly created requests are held in Pending status until reviewed by an authorized approver.

3 Leave Approval & Rejection Workflow

All pending leave requests are listed in the Leave Requests tab with their current status. Authorized roles (HR Manager, System Administrator) can process each request directly from the list.

  • View Details: Click the View row action to open the full request details including employee name, leave type, date range, days count, and reason.
  • Approve: Click the Approve action trigger on the request row. The status updates to Approved and the leave is registered against the employee's annual quota. Payroll engine picks this up automatically at the end of the month.
  • Reject: Click the Reject action trigger to decline the request. The status updates to Rejected and no quota deduction or payroll impact occurs.
⚠
Quota Enforcement:

If an employee has exhausted their annual quota for a given leave type, any additional leave requests of that type will either be automatically flagged or must be manually reviewed and re-classified as unpaid leave at the HR Manager's discretion.

4 Leave Status Reference & Payroll Impact

Status Meaning Payroll Impact
Pending Request submitted, awaiting HR/Admin decision. No payroll impact until a decision is made. Do not run payroll while requests are still pending.
Approved (Paid) Request approved for a leave type with Is Paid Leave ON. Full salary maintained for the leave period. Annual quota deducted accordingly.
Approved (Unpaid) Request approved for a leave type with Is Paid Leave OFF. Basic salary reduced proportionally for the leave days. No-pay deduction applied at payroll processing.
Rejected Request declined by HR/Admin. No payroll impact. No quota deduction. Employee is expected to report to work on the specified dates.

Module 07 · Chapter 07 — HR & Payroll Operations

Module 07: End-to-End Payroll Lifecycle, Staff Advances, Loans & Statutory Processing in Cinaway ERP

Target Audience HR Managers, Payroll Officers, Finance & Accounts Officers, System Administrators
Responsible Person HR Manager Accounts & Finance System Administrator
Objective Complete operational workflow covering recurring pay component setup, employee loans and salary advance disbursement, monthly batch payroll generation, automatic statutory deductions (EPF 8%/12%, ETF 3%, Gratuity provision), and payslip verification.
💰
Sri Lankan Statutory Payroll Compliance & Automated ERP Computation:

Under Sri Lankan Labor Law and Cinaway ERP's automated payroll architecture, statutory contributions are computed automatically on qualifying gross earnings. In addition to basic salary calculations, the engine executes real-time statutory deductions and provisions: Employee EPF (8%), Employer EPF (12%), Employer ETF (3%), and Gratuity provisions (Payment of Gratuity Act No. 12 of 1983). The payroll pipeline automatically reconciles with Biometric Attendance records (Module 05), Approved Leave days (Module 06), Active Staff Loans, and Approved Salary Advance disbursements before generating official monthly payslips.

1 Configuring Recurring & Custom Pay Components (Allowances & Deductions)

To configure recurring salary additions, variable allowances, or fixed payroll deductions, navigate to HR Module ➤ Pay Components.

From the Pay Components dashboard, click + Add Pay Component to open the configuration modal:

  • Component Name *: Enter a recognizable, standardized title (e.g., Transport Allowance, Attendance Incentive, Travelling Allowance, Sales Incentive, or Mobile Allowance).
  • Component Type *: Select the component classification from the dropdown:
    • Allowance / Addition: Adds directly to the employee's gross earnings before or after statutory baselines depending on taxability.
    • Deduction: Deducted from the employee's net pay (e.g., staff welfare, insurance, or uniform contributions).
  • Amount (LKR) *: Enter the recurring monthly numeric value in Sri Lankan Rupees.
  • Effective Date Range: Define the Effective From Date and Effective To Date. Use the year/month picker to set multi-year validity or contract-bound expiration.
  • Applicable Months: Select whether this component recurs every calendar month or applies only to specific seasonal cycles (e.g., New Year bonus components).
  • Default vs. Manual Assignment: Toggle whether the component automatically applies to all employees by default or is manually assigned to selected individual staff profiles.

Click Create Pay Component to register the rule. Click View on any component row to inspect assigned employees, effective date windows, and complete audit history via the 🛡 Audit History log.

2 Employee Loans Provisioning, Repayment Tenures & Installment Amortization

Cinaway ERP manages long-term staff loan facilities with automated monthly installment amortization. Navigate to HR Module ➤ Employee Loans.

To issue an employee loan facility, click + Create New Loan and complete all required fields:

  • Target Employee *: Search and select the eligible permanent employee from the staff directory.
  • Loan Amount (LKR) *: Input the approved principal loan sum (e.g., 50,000.00).
  • Start Date / Effective Month *: Select the payroll month in which the first installment deduction will trigger.
  • Repayment Tenure & Installments: Specify the total number of monthly installments or monthly deduction amount. The system calculates the monthly amortization deduction and tracks running principal balances.
  • Purpose & Remarks: Record the formal justification (e.g., Staff Emergency Medical Support, Motorcycle Purchase Facility, Education Assistance) and administrative remarks for executive audit trails.

Click Create Loan. The loan record is registered in Pending Approval status.

⚠
Loan Approval & Cancellation Authority:

An authorized administrator or HR Manager reviews pending loan requests directly on the Employee Loans dashboard. Click Approve to activate the loan into the active deduction cycle, or Cancel to reject the loan with mandatory audit remarks. Once approved, the monthly deduction is automatically locked into future payroll cycles until fully amortized.

Select Audit History on any loan row to review immutable timestamps, approver user IDs, and running installment ledger balances.

3 Staff Salary Advances: Application, Approval & Bank Account Settlement

For mid-month emergency salary draws, navigate to HR Module ➤ Salary Advances. The system automates advance requests, approver bank allocations, and automated month-end recoveries.

  • Create Advance Request: Click + Create Advance Request.

  • Statement Reconciliation: Monthly supplier statement balances can be matched against the ERP sub-ledger to verify pending payments, settled cheques, and approved debit notes before authorizing bulk electronic funds transfers (BOC PRN / CEFT).

5 Purchase Return Initiation & Original Bill Validation

When stock must be returned to the manufacturer or supplier due to damages, defects, or expiry, initiate a Purchase Return with strict validation:

  1. Access Return Module: Go to Procurement ➤ Purchase Returns and click + Initiate Purchase Return.
  2. Link Original Purchase Bill Reference *: Enter the original Purchase Bill Number. The system immediately retrieves the exact items, quantities, and cost prices invoiced on that bill.
  3. Strict Quantity Validation Protocol:
    ⚠
    Enforced Bill Cross-Validation: Cinaway ERP strictly enforces that return quantities cannot exceed the original purchased quantity on the selected bill minus any prior returns. Attempting to return unregistered items or excessive units is automatically rejected by the validation engine.
  4. Return Classification: Select the return reason: Damaged in Transit, Near-Expiry / Expired Stock, Manufacturing Defect, or Delivery Surplus / Billing Error.
  5. Submit for Approval: Click Submit Return for Authorization. The return request enters Pending Approval status.

6 Multi-Level Approval Workflow & Automated Balance Knock-Off

To preserve financial integrity, purchase returns require multi-tier operational and accounting authorization:

  • Verification & Physical Inspection: The Warehouse Manager inspects the quarantined return stock and verifies quantities against the return request.
  • Financial Authorization: The Accounts Payable Lead reviews the return valuation and clicks ✅ Approve Purchase Return.
  • Automated Ledger Reconciliations on Approval:
    Debit: Account 2001 (Trade Creditors / Accounts Payable) — LKR Return Value
    Credit: Account 1300 (Merchandise Inventory Asset) — LKR Return Landed Cost
    The supplier's payable balance is reduced immediately, and physical inventory is depleted from warehouse stock.
  • Debit Note & Return Gate Pass: The system automatically issues an audited Supplier Debit Note and prints a Goods Return Gate Pass authorizing physical stock removal during supplier collection.
